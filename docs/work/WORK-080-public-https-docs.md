# WORK-080 — клиентская инструкция публичного HTTPS

- Родитель: TASK-003; запрос пользователя от 19.10.2026 — обычный HTTPS,
  отдельные токены, без Tailscale для второго компьютера.
- Роль: аналитик документации; исполнитель publicdocs080.
- Статус: выполнено, передано на независимое ревью координатору/079.
- Область записи: только `/private/tmp/accord-public-078/docs/`.
- Модель: унаследованная; именованные Claude-модели в этой среде не закреплены.

## Входы и принятые условия

Прочитаны AGENTS самостоятельного Accord, профиль аналитика, общий процесс,
parallel-work, design-first; локальные client-setup, second-pc, handoff,
receiver-agent и CLI-контракты токена прочитаны без изменений.
Tandem off имеет приоритет над процессом соседнего Davinci.

Координатор устанавливает публичный HTTPS на IPv4:443 с доверенным
сертификатом и автоматическим продлением. Здесь это входное условие, а не
проверенный факт: live-развёртывание не выполнялось и PASS ему не выдан.
Live binary остаётся C2 `1e9025c`, schema2, 12 MCP tools; токены индивидуальные.
Адрес доставляется в новом private `connection.json`, в репозитории — заглушка.

## Результат

- `public-https.md`: короткая смена адреса для уже получившего старый пакет,
  точное изменение `--server`, сохранение клиента/токена, диагностика,
  scoped synthetic smoke и запрет считать конфиг доказательством подключения.
- `second-pc.md`: предложенная полная замена прежнего документа; пять клиентов,
  проверка SHA, POSIX-права, Windows ACL/env и отдельный CLI-процесс.
- JSON не объявлен автоматически читаемым клиентом: origin переносится в MCP
  args; старые Tailscale/8443 шаги явно заменены.

## Проверки и ограничения

- PASS: ручная сверка аргументов с существующими клиентскими контрактами;
  Windows и POSIX секрет не попадает в literal аргументы/TOML.
- PASS: документы не содержат реального origin/IP, токенов, SSH-данных;
  изменения ограничены тремя заявленными Markdown-файлами.
- NOT-RUN: фактический публичный TLS/MCP, физический второй ПК, Windows runtime,
  совместный двухмашинный тест; их выполняет координатор/получатель.
- N/A: продуктовый дизайн/UI, Go-код, миграция БД, Git/публикация, серверные правки.

## Передача

сверяет документы с фактическими proxy/сертификатом и результатом проверок,
обновляет старые client-setup/handoff/receiver-agent ссылкой на новый порядок.
Хеши файлов зафиксированы в сообщении передачи; после заморозки записи прекращены.

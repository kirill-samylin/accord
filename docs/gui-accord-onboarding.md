# GUI: совместная работа через Accord

Историческая инструкция ручного MCP-подключения TASK012. Для текущего сервера
schema5 и управляемых агентов используйте [managed-worker-guide.md](managed-worker-guide.md)
и фактический [TASK013](TASK-013-managed-agents.md); старые пакеты schema4 ниже
не предназначены для установки нового worker.

Инструкция подключения, 22.10.2026. Подтверждённый пользователем GUI — локальный
проект «Давинчи» в каталоге `/Users/shagi/Desktop/Project/davinci-gui-`.
Второй участник использует Windows и Claude Code. Сам этот документ не
подтверждает подключение: точный ID проекта, private параметры и фактические
проверки фиксирует координатор. Второй физический компьютер **NOT-RUN**.

## Что настраивается один раз

У GUI один общий проект Accord: задачи, участники, профили и история общие.
У каждого человека своя локальная копия Git-репозитория, собственный токен
и собственные процессы агентов. Сервер Accord на компьютеры не устанавливают.
Для подключения через интернет достаточно обычного HTTPS; Tailscale не нужен.

Владелец проекта создаёт GUI в каталоге Accord, добавляет безопасную ссылку на
Git-репозиторий и выдаёт участникам membership. Ссылка хранится как метаданные:
Accord не клонирует репозиторий и не выдаёт доступ к Git. Репозиторий может
содержать несколько приложений; это не повод создавать отдельный проект
Accord для каждого компьютера.

Для каждого человека оператор выдаёт отдельный credential. Участник сообщает
владельцу только несекретный identity ID; владелец добавляет его в GUI как
`editor` для совместной разработки или `viewer` для чтения. Роль `owner` нужна
для управления проектом и участниками. Имена людей/машин не заменяют identity.

## Что получить второму участнику

По защищённому каналу передаются:

- точный HTTPS origin общего сервера;
- неизменяемый ID проекта GUI вида `p_…` и scoped ссылка на его панель;
- собственный token file, его machine label, срок и identity ID;
- проверенный клиент `agent-board` для ОС/архитектуры и его SHA256;
- ссылка на Git-репозиторий и отдельное разрешение читать/писать Git;
- при назначениях профилям — актуальные ID/version и роль выбранного профиля.

Origin, токен и готовые настройки с реальным адресом не добавляют в Git,
чат, общий отчёт или скриншоты. В этом документе только заглушки. Токен
первого человека не копируют второму. Локальный путь к GUI у каждого свой.

Старые архивы из [second-pc.md](second-pc.md) и версии `1e9025c`/`6245829`
устарели для нынешних ресурсов профилей, координации и дедупликации. Нужен
клиент проверенного TASK012-релиза или последующего совместимого релиза.
Оператор сверяет SHA256 и вывод `agent-board capabilities --json`:
`project_registry:1`, `project_acl:1`, `registry_schema:[1]`,
`agent_profiles:1`, `coordination:1`, `deduplication:1`, `board_schema:[4]`.
Capabilities не заменяют проверку происхождения binary и реального запуска.

## Только браузер

Откройте выданную scoped ссылку, войдите своим токеном или token file и выберите
GUI. В каталоге должен быть именно общий проект и выданная роль. В «Команде»
видно участие и текущие задачи; профиль сам по себе не означает живого агента.

Для просмотра, обсуждения и разрешённых действий в панели MCP не нужен.
Для правки кода клонируйте GUI обычным Git-клиентом с собственным доступом.
Один вход в браузере не подключает локального агента автоматически.

## Codex: macOS и Linux

Полученный binary находится локально; token file — вне checkout. Каталог
секретов должен иметь права `0700`, файл токена — `0600`. Используйте абсолютные
пути. Откройте GUI как доверенный проект Codex и добавьте в проектный
`.codex/config.toml` следующий раздел, сохранив прежние настройки:

```toml
[mcp_servers.accord_gui]
command = "/ABSOLUTE/PATH/agent-board"
args = ["mcp", "--server", "https://ACCORD_ORIGIN", "--project", "PROJECT_ID", "--token-file", "/ABSOLUTE/PRIVATE/PATH/gui.token"]
required = true
```

Замените все заглушки приватными параметрами. `--server` — origin, без `/mcp`
и без project path. `--project` — точный ID GUI, обязателен: без него клиент
обратится к default, а не к GUI. Выбор GUI в браузере на MCP не влияет.

Настройка содержит только путь к секрету, не его значение. Не коммитьте файл
с реальным origin/локальными путями; используйте локальное исключение Git для
своего конфигурационного файла, сохраняя правила репозитория. Если файл уже
tracked, сначала согласуйте отдельную локальную конфигурацию с координатором.

Перезапустите соответствующий локальный Codex. Для самостоятельного CLI
запуска после проверки списка MCP используйте отдельный процесс исполнителя.
Общий проектный раздел не доказывает, что приложение запускает независимый
bridge для каждого внутреннего субагента: это нужно проверить в самом клиенте.

Официальный формат и доверие проекту:
[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp).
Иное приложение, включая Claude Code, требует собственной подтверждённой
конфигурации; этот TOML не объявляется универсальным MCP-форматом.

## Claude Code: Windows

Получите Windows binary нужной архитектуры и сверьте его SHA256. Храните
token file вне checkout, с ACL только для своей учётной записи и необходимых
системных администраторов. Не печатайте его содержимое. Проверка POSIX-прав
не проверяет Windows ACL, поэтому здесь используется окружение процесса.

В GUI подготовлен общий `.mcp.json` без секретов и адресов:

```json
{
  "mcpServers": {
    "accord_gui": {
      "type": "stdio",
      "command": "${ACCORD_CLIENT}",
      "args": ["mcp", "--server", "${ACCORD_ORIGIN}", "--project", "${ACCORD_PROJECT_ID}"],
      "env": {"AGENT_BOARD_TOKEN": "${AGENT_BOARD_TOKEN}"}
    }
  }
}
```

Настройка не подменяет Codex TOML. Claude поддерживает project scope и `${VAR}`
в command/args/env по [официальной документации](https://code.claude.com/docs/en/mcp).
Переменные без значений нужно заполнить до запуска, а не оставлять заглушками.
Полная инструкция для коллеги находится в GUI: `docs/agents/accord.md`.

Из PowerShell в корне GUI, с выданными private файлами:

```powershell
$AccordGuiPrivate = Join-Path $env:USERPROFILE '.config\accord-gui'
$AccordGuiNames = @('ACCORD_CLIENT', 'ACCORD_ORIGIN', 'ACCORD_PROJECT_ID', 'AGENT_BOARD_TOKEN')
$AccordGuiPrevious = @{}
foreach ($AccordGuiName in $AccordGuiNames) {
  $AccordGuiPrevious[$AccordGuiName] = [Environment]::GetEnvironmentVariable($AccordGuiName, 'Process')
}
try {
  $AccordGuiConnection = Get-Content -Raw (Join-Path $AccordGuiPrivate 'connection.json') | ConvertFrom-Json
  $env:ACCORD_CLIENT = Join-Path $env:USERPROFILE 'accord-client\agent-board.exe'
  $env:ACCORD_ORIGIN = $AccordGuiConnection.origin
  $env:ACCORD_PROJECT_ID = $AccordGuiConnection.project_id
  $env:AGENT_BOARD_TOKEN = (Get-Content -Raw (Join-Path $AccordGuiPrivate 'gui.token')).Trim()
  foreach ($AccordGuiName in $AccordGuiNames) {
    if ([string]::IsNullOrWhiteSpace([Environment]::GetEnvironmentVariable($AccordGuiName, 'Process'))) {
      throw "Не задан обязательный параметр $AccordGuiName"
    }
  }
  if (!(Test-Path -LiteralPath $env:ACCORD_CLIENT -PathType Leaf)) { throw 'Не найден клиент Accord' }
  claude
} finally {
  foreach ($AccordGuiName in $AccordGuiNames) {
    [Environment]::SetEnvironmentVariable($AccordGuiName, $AccordGuiPrevious[$AccordGuiName], 'Process')
  }
  $AccordGuiConnection = $null
}
```

Не вставляйте токен в JSON/TOML, команды, профиль PowerShell или literal env.
Уже открытое графическое приложение не получает окружение этого терминала.
Cross-build не подтверждает Windows runtime; фактический запуск на ПК второго
участника проверяется отдельно.

## Первый запуск агента

Сначала проверяют readiness через выданный HTTPS origin с обычной проверкой
сертификата, MCP initialize и каталог инструментов/ресурсов. Не выключайте TLS
и не используйте обход ошибки сертификата. Запись в настройках сама по себе
не доказывает подключение.

Агент получает следующую инструкцию с подставленными несекретными параметрами:

> Работаешь с GUI через MCP `accord_gui`, закреплённый за точным ID проекта.
> Не раскрывай токен или приватные параметры. Сначала вызови `describe` с новой
> уникальной парой request_id/run_id, своей ролью и machine label из выдачи.
> Если назначен профиль, передай вместе его актуальные profile_id и
> profile_version, с совпадающей ролью; прочитай возвращённый snapshot.
> Проверь project scope по конфигурации, прочитай задачи и `accord://team`.
> Новую работу сначала сравни через `accord://similar?title=…`, затем создай
> только недостающую задачу. До правок получи свою задачу через `next` и
> проверь lease/generation, assignment и предупреждения. Если задача занята,
> не выполняй её параллельно. При LEASE_UNCERTAIN/LEASE_LOST немедленно
> останови локальные изменения и сообщи координатору.

Через stdio bridge `session_id` можно опускать: он подставляет только свою
сессию. Для прямого HTTP требуется явный session_id и отдельный heartbeat;
этот вариант не включают параллельно с bridge для одной и той же работы.
В ресурсах пробел кодируют `%20`, literal `+` — `%2B`.

Один bridge держит одну board-сессию с одной ролью. Самостоятельным разработчику,
ревьюеру и тестировщику нужны отдельные процессы bridge и новые `describe`.
При смене роли bridge перезапускают. Процесс bridge завершается вместе с
исполнителем; живой общий bridge не доказывает, что каждый его клиент работает.

В `describe.role` допустимы только серверные роли coordinator/analyst/architect/
developer/reviewer/tester/human. Специализации GUI devops/security/design-reviewer/
llm-quality не передают туда как есть: координатор явно выбирает поддержанную
роль очереди и назначение профиля, сохраняя локальные инструкции специализации.

## Как работать вдвоём

1. Координатор делит задачи и области записи. Каждый работает в собственной
   ветке/локальной копии, получает задачу через свой `next` и фиксирует результат.
2. В `create` предупреждение о похожести требует открыть похожую задачу.
   Если это дубль, свою свободную задачу связывают `duplicate_of` с основной.
   В strict-режиме force требует обоснованную причину, а не обход проверки.
3. Предупреждение `area_overlap` или похожая работа у другого участника требует
   сверить объём до правок. Области — метки; Accord не блокирует файлы на диске
   и не гарантирует обнаружение всех перефразированных дублей.
4. Разработчик завершает работу с реальным полным commit SHA и evidence.
   Human/coordinator явно создаёт проверку reviewer текущего результата.
   Независимый reviewer работает в другой server-generated сессии и проверяет
   именно target SHA/generation. Профиль не заменяет независимость сессии.
5. После актуального положительного review явно создают QA. Тестировщик
   проверяет тот же результат и фиксирует фактические PASS/FAIL/NOT-RUN/N/A.
   Новый SHA разработчика требует актуальных проверок, старый verdict не
   является проверкой новой версии.

Назначение pinned-профилю требует точных ID/version/role. После редактирования
профиля ожидающее назначение может потребовать явного переназначения; новые
клиенты не должны подменять это произвольным именем профиля. Уже открытая
сессия сохраняет неизменный snapshot. Отзыв доступа делают через ACL/credential,
а не архивированием профиля.

## Проверка подключения и границы

Readiness, initialize/tools/resources, свежий `describe` и scoped чтения
проверяют отдельно от бизнес-сценария. Любые пробные mutations выполняют в
новом явно обозначенном TEST-эпике с последующей отменой только своей работы;
чужие задачи/аренды не используют для smoke. Новые process/E2E проверки
репозитория запускаются отдельным тестировщиком после независимого approve.

После настройки второго ПК требуется реальная совместная проверка: два
человека на двух физических машинах одновременно запрашивают одну тестовую
developer-задачу разными сессиями; только одна получает аренду. Проверяют
heartbeat, остановку bridge, истечение и новый generation. Два процесса на
одном Mac эту проверку не заменяют. Отдельно записывают версию ОС, приложения,
SHA клиента и результаты без секретов/сырых ответов доски.

При ошибке 401 оператор проверяет token expiry/revoke; при 403 — ACL и точный
Host/Origin. При неверном проекте проверяют `--project`, а не переключатель
браузера. При назначении, недоступном `next`, проверяют role/profile version
и причины координации. Не запускайте локальный `serve` и не подключайте Tandem.

Accord координирует pull-цикл `describe → next → result`; он не запускает
агентов, не выполняет код, не синхронизирует Git и не гарантирует остановку
файловых правок при потере lease. Живой heartbeat означает присутствие сессии,
не доказанную работу OS-процесса/модели. Физический второй ПК и фактическая
совместимость выбранного приложения остаются NOT-RUN до собственного прогона.

Чтобы приостановить работу, исполнитель сначала останавливает локальные правки
и явно освобождает задачу через `release`. После этого координатор меняет
объём/назначение/зависимости по правилам доступа; исполнитель перечитывает
актуальную задачу и получает её через `next`. Изменение задачи в панели не
посылает гарантированную команду работающей модели и не прерывает OS-процесс.

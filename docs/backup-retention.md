# Ограниченное локальное хранение Accord — WORK-062

Это подготовленная политика `infra/accord/backup.py`, ещё **не развёрнутая**.
Ранее установленная политика168 копий сохраняет своё фактическое поведение
до отдельного проверенного выпуска. Раздел deployment про168 описывает прежний
wrapper; координатор синхронизирует его при интеграции принятой версии.
Production/Tandem backups в WORK-062 не менялись. Внешнего/offsite хранилища нет:
локальные копии не защищают от потери VPS/диска и не являются DR.

## Точные правила

| Ограничение | Поведение |
| --- | --- |
| Свежие часовые | Самая новая verified пара в каждом из24 UTC часовых buckets, включая текущий час |
| Дневные | Самая новая verified пара за каждую из7 UTC календарных дат, включая сегодня |
| Общий бюджет | 5368709120 bytes (5GiB), сумма логических размеров verified DB+SHA256 |
| Защита | Последние `min(2, count)` verified пары по timestamp/mtime/имени не удаляются |
| Давность | Hourly/daily — best-effort; при нехватке бюджета/места удаляются старейшие незашищённые preferred пары |
| Минимум для новой копии | Существующие защищённые пары + оценка новой копии укладываются в бюджет; хватает физически свободного места |

Часовой интервал начинается в начале текущего UTC часа минус23 часа. Дневной —
сегодня UTC и6 предыдущих дат; это не обещание168часов или7полных суток.
Одна пара может одновременно покрывать hourly и daily. Повторные ручные запуски
в одном часу не создают новый hourly slot; защитные2 пары могут временно дать
дополнительную пару в том же часу. Будущие timestamp не заполняют часовые/дневные
slots, но2 самых новых по этому порядку остаются защищены. В пределах одной секунды
сначала сравнивается mtime наносекунд, затем UUID; случайный UUID не должен
переставлять последнюю копию за более раннюю. Источник времени — UTC часы
VPS: синхронизация часов важна, автоматического переименования/исправления нет.
Семь дат и24часа не гарантируются ни при больших БД, ни при пропуске запусков.

При пустом каталоге первая полная проверенная durable копия успешна; журнал
явно показывает `redundancy: 1/2`. Следующий успешный запуск доводит до `2/2`.
Существующая единственная восстановимая копия не удаляется ради новой.
Если места/бюджета недостаточно без удаления защищённых копий, запуск FAIL.

Входной измеренный размер годовой БД —173051904 bytes:168 полных копий требуют
29072719872 bytes, больше всего диска VPS21028065280 bytes. Новый бюджет5GiB
соизмерим с диском; это не обещание будущего неизменного размера БД.

## Управляемые файлы и проверка

Удалять разрешено только пары `board-YYYYMMDDTHHMMSSZ-<32lowerhex>.db` и точный
`<name>.sha256`. Оба файла: принадлежат текущему uid, regular,0600, один hardlink;
каталог принадлежит uid,0700. Файлы открываются `O_NOFOLLOW|O_NONBLOCK` через
дескриптор каталога. Симлинки, FIFO, неверные owner/mode, hardlinks, лишние SQLite
sidecars, повреждённые/неполные пары и неправильные даты не управляются.

Для каждого кандидата потоково сверяются точный SHA256 и полная SQLite
`PRAGMA integrity_check`; read-only `immutable=1` использует ранее открытый FD
через системный `/dev/fd`, без создания sidecars. Метаданные проверяются до/после
чтения; перед удалением пара проверяется повторно и сравнивается inode/метаданные.
Одновременно работающие процессы с тем же uid и root остаются доверенными:
POSIX не предоставляет atomic unlink-if-inode; приватный0700 каталог и общий
maintenance lock — граница этого решения. Source writer lock не берётся: online
snapshot реализует согласованный Go CLI через VACUUM INTO, не cp живой БД/WAL.

Другие имена, включая pre-upgrade/pre-migration snapshots, чужие/неподходящие
файлы и повреждённые пары **никогда не удаляются этой ротацией**. Они не входят
в5GiB managed budget, но занимают реальное свободное место. `ignored` считает
непроверенные DB с управляемым шаблоном; это не полный каталог посторонних файлов.
Их разбор, перенос или удаление — отдельный операторский план. Автоматического
«аварийного удаления всего старого», staging-файлов и копий Tandem нет.

## Защита от disk-full

Перед копированием вычисляется `estimate = size(board.db) + size(board.db-wal)
+ 16MiB`. Source DB/WAL также должны быть owned regular0600 single-link без
симлинков; отсутствующий WAL допустим. Требуется `free >= 2*estimate + 512MiB`:
полная выходная копия, сопоставимый рабочий запас SQLite и свободный floor.
Для173051904-byte DB без WAL estimate189829120, required free916529152 bytes.

Сначала в памяти строится **полный допустимый план** удаления: устаревшие slots,
затем старейшие preferred сверх лимита. Если план невозможен с сохранением
защищённых пар, до любых удалений/запуска child выдаётся
`insufficient_space_preserving_two`. Прогноз освобождения использует меньший из
логического размера и выделенных блоков каждого файла, чтобы sparse-файл не
обещал несуществующее место. Все файлы outside policy учитываются через free.

Только после успешного расчёта удаляются выбранные verified пары; после каждой
пары fsync каталога. DB/WAL и free перечитываются перед CLI; рост source может
дать `space_changed_before_copy` без запуска копии. Старые защищённые2 сохранятся,
но уже выполненная безопасная ротация не откатывается. Проверка space — preflight,
не kernel reservation/дисковая квота: другие процессы и живой WAL могут расти.
512MiB floor не гарантирует работу произвольно растущих других сервисов.

CLI создаёт consistent checked0600 snapshot и fsync. Wrapper повторяет integrity,
создаёт SHA256 через O_EXCL0600, fsync обоих файлов и каталога, проверяет пару.
До принятия новой пары проверяются реальный размер≤estimate и free≥floor;
превышение — `copy_exceeded_reserve`, новая непринятая пара очищается. При
catchable ошибке wrapper удаляет только наблюдённые собственные inode этого
запуска, сохраняя замену оператора. CLI отвечает за собственный private staging.
При SIGKILL/потере питания возможен orphan; он сохраняется для оператора.
После успешной публикации ещё раз сворачиваются дубли slots с защитой latest2.

Ошибки журнала содержат только фиксированный код/тип исключения. stdout/stderr
CLI не попадают в журнал wrapper; содержимое БД, токены, paths exception не
логируются. FAIL остаётся systemd failure, повтор запуска — обычный timer/manual.
MemoryMax256M, CPUQuota50%, TimeoutStartSec5min **не меняются**. Проверка большого
старого каталога читает все подходящие копии, а удаляемые проверяет повторно:
Linux/VPS время и5минутный deadline ещё нужно измерить до включения политики.

## План перед отдельным выпуском

`--plan` не запускает child, не создаёт checksum, не удаляет файлы и не создаёт
maintenance lock. Он требует уже существующий owned0600 lock, ждёт общий lock,
сверяет файлы и печатает JSON с free/estimate/reserve/floor/budget, `protected`,
`delete`, verified/ignored. При невозможности безопасного плана — FAIL без записи.
Это расчёт по текущему состоянию; следующий apply пересчитает его заново.

После независимого review root сначала проверяет plan **проверенной новой**
версии, ещё не подменяя установленный helper. Например, скопировав проверенный
root-owned candidate в отдельное согласованное место с неизменяемыми правами:

```sh
sudo -u accord /usr/bin/python3 /path/to/reviewed/backup.py --plan
```

Путь-пример не означает, что файл уже установлен. Root сверяет protected, delete,
размеры и наличие посторонних/pre-upgrade копий; применение/удаления требуют
отдельного шага. `--plan` может долго ждать работающий backup/recovery lock;
его следует запускать в контролируемое оператором время. Independent source
review, Linux runtime, реальный free/limits/time и restore drill для этой версии
здесь не подменены локальными synthetic тестами.

## Воспроизведение локальных проверок

```sh
python3 -W error::ResourceWarning -m unittest discover -s tests/infra -p 'test_backup*.py' -v
```

Stdlib unit/integration используют только временные synthetic SQLite/файлы,
малый отдельный child-copier и подставленные оценки места. Это проверка wrapper,
а не новый продуктовый E2E, реальный Go CLI, production restore или VPS capacity.
API сверены с [Python os](https://docs.python.org/3/library/os.html),
[Python sqlite3](https://docs.python.org/3/library/sqlite3.html) и
[SQLite URI immutable](https://www.sqlite.org/uri.html).

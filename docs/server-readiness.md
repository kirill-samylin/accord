## Разрывы до работы с двух ПК

1. Нужен выбор общего сервиса: продолжить прежний Tandem либо разворачивать
   Accord. Они не синхронизируют БД и не являются взаимозаменяемыми MCP-серверами.
2. Для Accord нужен один постоянно работающий экземпляр с одной приватной БД,
   закрытым сетевым доступом, проверенным HTTPS-маршрутом и отдельными токенами
   машин. Запуск двух независимых локальных серверов создаст две разные очереди.
3. Для Accord ещё предстоят Linux runtime-проверка, эксплуатационный запуск,
   backup/restore, отзыв токена и end-to-end проверка удалённых клиентов.
   Локальный loopback-пилот и успешный health прежнего Tandem этого не доказывают.
4. Для прежнего Tandem доступ даёт членство в доверенной Tailscale-сети и
   capability доски. Auth-none не разделяет права двух людей; TTL0 исключает
   автоматическую передачу зависшего claim. Ручное освобождение допустимо
   только после остановки старого исполнителя — ограничение прежнего решения.
5. На втором физическом ПК требуется проверить VPN/HTTPS, MCP-подключение и
   видимость одной synthetic задачи с конкурирующим claim. Такой ПК этому
   запуску недоступен; результат — NOT-RUN. Повторный процесс на этом Mac
   проверкой второго компьютера не считается.

Адреса частной сети, capability доски, SSH-ключи, bearer-токены и содержимое
приватного client.json в отчёт/Git не включены. Никаких deploy, restart,

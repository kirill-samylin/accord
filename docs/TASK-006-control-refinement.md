## Дополнение browser read API

`GET|HEAD /web/data/dashboard`, без query-параметров, с текущей browser cookie
и действующей board-сессией. JSON: `overview: ControlOverview`,
`agents: ControlSessionsPage`, `activity: RecentEventsPage`.
Агенты: `kind=agent`, `state=active`, `limit=6`; события: `limit=20`.
Коллекции имеют собственные `observed_at`; совместной атомарности трёх чтений
не обещаем. Ошибка любой части завершает весь запрос ошибкой.
SSR и JSON используют общий backend reader. GET не продлевает аренды/сессии.
Старый `/web/data/overview` сохраняет wire-контракт.

Карточка задачи T-* читает до 10 последних событий с точным `task_key`.
Для полного журнала есть ссылка на `/web/activity?task_key=…`; чтение
не продлевает владение, незаполненная история явно показывает пустое состояние.
Эпики E-* текущий event reader как фильтр не поддерживает; их карточки
сохраняют прежнее поведение.

Клиент по умолчанию обновляет прежние счётчики. Явный переключатель включает
обновление панелей через dashboard в том же цикле, одним запросом вместо
overview. Без параллельных циклов и дополнительного heartbeat. При ошибке
последние данные сохраняются с сообщением; 401/истёкшая сессия останавливают
обновление. Текст из API вставляется безопасными текстовыми DOM-операциями.

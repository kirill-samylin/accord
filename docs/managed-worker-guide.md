# Подключить компьютер к управлению агентами

Инструкция TASK013. Нужен совместимый сервер Accord с `managed_agents:1` и
board schema5, а также новый клиент `agent-board`. Исходники новой функции
сами не обновляют установленный сервер TASK012. Фактический статус —
[TASK013](TASK-013-managed-agents.md). Windows и второй физический компьютер
требуют отдельного запуска; сборка `.exe` не подтверждает их работоспособность.

## Как это работает

На каждом компьютере работает локальный исполнитель Accord — worker. Он
получает команды общего проекта и запускает собственные процессы Codex или
Claude Code. В панели видны компьютер, задание, состояние процесса и история
доставки команд. Уже открытые чаты и процессы других приложений не подключаются.

Для удалённой работы компьютер должен быть включён, иметь связь и запущенный
worker. Открывать порт или выдавать SSH-доступ не требуется. Worker запускается
от обычной учётной записи владельца, с его локальным входом в Codex/Claude.
Accord не получает пароль, подписку или API-ключ модели.

У каждого ПК своя рабочая копия GUI. Общая доска передаёт задания и команды,
а изменения файлов передаются через обычный Git. Одинаковое имя рабочей папки
в Accord не синхронизирует файлы между компьютерами.

Пользователь выбрал взаимное управление: оба участника могут управлять обоими
компьютерами. Каждый владелец явно разрешает второго участника на своём ПК.
Одна роль «Редактор» на доске этого разрешения не выдаёт.

## Подготовить локальные файлы

Нужны собственный токен участника GUI, точный project ID и HTTPS origin из
индивидуального `connection.json`. Токен другого человека не копируют.
Доступ к Git и локальная копия GUI подготавливаются обычным способом.

На Mac храните настройки, токен и state в приватном каталоге вне Git: каталог
`0700`, файлы `0600`. На Windows нужны настоящие ACL: владелец — текущая учётная
запись; доступ только ей, SYSTEM и необходимым локальным администраторам.
Unix mode bits на Windows не заменяют ACL, worker проверяет DACL.
Не публикуйте токен, реальный origin, полный config или state.

Настройка `worker.json` для Mac (все заглушки заменяются локально):

```json
{
  "server": "https://ACCORD_ORIGIN",
  "project": "p_PROJECT_ID_FROM_CONNECTION",
  "token_file": "/ABSOLUTE/PRIVATE/gui.token",
  "state_dir": "/ABSOLUTE/PRIVATE/worker-state",
  "name": "mac-main",
  "machine": "MACHINE_FROM_CONNECTION",
  "controllers": [],
  "executables": {"codex": "/ABSOLUTE/PATH/TO/codex"},
  "codex_sandbox": "workspace-write",
  "workspaces": {
    "gui": {"path": "/ABSOLUTE/PATH/TO/gui", "providers": ["codex"]}
  }
}
```

`workspace-write` означает явное локальное разрешение править выбранную рабочую
копию. Для проверки чтения выберите `read-only`. Другие native правила и
подтверждения не отключаются; отказ разрешения виден как ошибка работы агента.
Модель по умолчанию выбирает установленный CLI. Если профиль содержит конкретную
модель, добавьте её в локальный `models`, например
`{"codex":["EXACT_LOCALLY_ALLOWED_MODEL"]}`. Worker не меняет её на другую молча.

Для native Windows Claude Code замените соответствующие поля:

```json
{
  "server": "https://ACCORD_ORIGIN",
  "project": "p_PROJECT_ID_FROM_CONNECTION",
  "token_file": "C:\\Users\\USER\\.config\\accord-gui\\gui.token",
  "state_dir": "C:\\Users\\USER\\.config\\accord-gui\\worker-state",
  "name": "pc-2",
  "machine": "MACHINE_FROM_CONNECTION",
  "controllers": [],
  "executables": {"claude": "C:\\ABSOLUTE\\PATH\\claude.exe"},
  "claude_permission_mode": "default",
  "workspaces": {
    "gui": {"path": "C:\\Users\\USER\\Projects\\gui", "providers": ["claude"]}
  }
}
```

Нужен native `.exe`; `.cmd`/`.bat`, UNC/network roots и ссылки вместо разрешённой
папки не принимаются. `acceptEdits` можно выбрать только локальным решением
владельца вместо `default`; это не разрешение обходить остальные подтверждения.
Пути и параметры запуска из браузера не принимаются.

## Разрешить управление друг другу

Выполните на каждом ПК своим клиентом, передавая абсолютный путь config:

```text
agent-board worker identity --config PRIVATE_WORKER_JSON
agent-board worker enroll --config PRIVATE_WORKER_JSON
```

На Windows команда начинается с пути к `agent-board.exe`. `identity` показывает
несекретный project-local код управления. Это не token, не registry identity ID
из старой выдачи доступа и не ID профиля. Владелец автоматически может управлять
своим host даже с пустым `controllers` на первом шаге.

Обменяйтесь этими несекретными кодами. На каждом ПК добавьте код второго человека
в локальный `controllers`, затем выполните:

```text
agent-board worker consent --config PRIVATE_WORKER_JSON
agent-board worker run --config PRIVATE_WORKER_JSON
```

`consent` обновляет именно ранее подключённый компьютер через его локальный proof.
Уже работающий worker сначала штатно завершите; второй процесс с тем же state
не запускается. Worker хранит настройки подключения и подтверждения команд в
`state_dir`. Не удаляйте и не копируйте этот каталог ради обхода занятого процесса.

После штатного перезапуска подключение иногда занимает до35 секунд: worker
дожидается окончания прежнего серверного разрешения. Во время ожидания агент
не запускается. Живой или неоднозначно завершившийся исполнитель автоматически
не заменяется.

Оставьте `worker run` работающим. Автозапуск worker при входе в ОС этой командой
не устанавливается. Выход из его терминала останавливает управляемые процессы;
для фоновой службы нужна отдельная настройка от владельца ПК.

## Управление в Accord

Откройте проект GUI → «Управление». Выберите компьютер, разрешённую рабочую
копию и CLI, актуальный профиль агента, напишите задание и нажмите «Запустить».
Один checkout одновременно занят одной работой; для параллельной записи нужен
другой отдельно разрешённый checkout. Версия инструкций профиля закрепляется
при запуске; редактирование профиля не переписывает начатый диалог.

«Остановить» отправляет команду worker. Пока она не подтверждена, панель
показывает ожидание. Принудительное завершение отображается отдельно. Другие
процессы с таким же именем не завершаются.

На Mac/Linux остановка охватывает управляемый CLI и его группу процессов.
Отдельная фоновая служба, которая вышла из этой группы через `setsid`/double-fork,
требует локальной проверки и завершения владельцем. Это не гарантия остановки
всех возможных фоновых писателей в папке. Локальная блокировка checkout
согласует запуски worker; она не является системным запретом записи других
программ. Windows Job Object удерживает созданное им дерево процессов.

«Продолжить» использует тот же сохранённый native диалог и рабочую копию.
Без подтверждённой остановки или сохранённого session ID новый чат не выдаётся
за продолжение. После потери аренды доски агент получает новую сессию и заново
проверяет право на задачу.

Подтверждённое завершение или остановка освобождает рабочую сессию этой попытки
и её занятую задачу. Незавершённая задача возвращается в очередь; отметка «Выполнено» не
появляется автоматически. При продолжении агент получает новое право на работу
и проверяет актуальное назначение задачи. Если завершение не подтверждено,
система сохраняет прежнюю защиту и требует восстановления. После изменения
профиля координатору иногда нужно обновить назначение самой задачи.

«Передать уточнение» сохраняет сообщение в очереди. Для работающего CLI оно
доставляется после текущего шага диалога. Для остановленной работы очередь
доставляется при «Продолжить». Чтобы прервать текущую работу раньше, используйте
отдельную остановку. «Доставлено» означает передачу в native диалог, а не
согласие модели или выполнение требования.

Получение run не заменяет `describe → next` на доске. Код задачи — контекст,
а не аренда. Успешный выход CLI не закрывает задачу и не выдаёт review approve.
Автор, reviewer и tester используют отдельные процессы/серверные сессии.

## Первая проверка двух компьютеров

После обновления сервера и подключения обоих worker убедитесь, что оба
участника видят оба компьютера и могут открыть форму запуска на каждом.
Для Mac Codex выберите профиль с provider OpenAI, для Windows Claude — профиль
Anthropic; конкретная модель должна быть разрешена владельцем локально.

Сначала используйте отдельную тестовую рабочую копию с простым README, без
продуктовых правок. Первый участник запускает чтение README на Windows,
второй — на Mac. Проверьте появление подтверждённого начала работы и ответа.

Затем запустите достаточно длинное тестовое поручение, чтобы проверить
«Остановить». Дождитесь подтверждённой остановки; ожидание команды и offline
не являются её выполнением. Передайте уточнение остановленной работе: оно
должно оставаться в очереди до «Продолжить». После продолжения проверьте ответ
на уточнение и сохранение native conversation ID. Для работы над задачей
продолжение требует нового подтверждения права; при успешном получении аренда
новая, даже когда native диалог остаётся прежним.

Повторите управление с другой учётной записи, поменяв компьютеры местами.
Сохраните только результат, версии клиентов и несекретные коды запусков.
Не пересылайте config/state, токены или полный native transcript.
До этой проверки фактическая работа native Windows и двух физических ПК
остаётся NOT-RUN независимо от сборки `.exe` и локальных тестов на Mac.

## Сбой и восстановление

При пропаже управления worker прекращает свои процессы по локальному watchdog;
offline-интерфейс не обещает мгновенную удалённую остановку. Статус компьютера
отражает последнее наблюдение сервера, а не часы браузера.

После аварии между запуском процесса и записью подтверждения возникает
«Требуется восстановление». Повтор команды, перезапуск с чистым state или новый
host не являются доказательством, что старый процесс остановлен. Worker удерживает
локальную защиту checkout, общую для разных enrollment. Проверьте свои процессы
и локальный журнал с оператором; не убивайте процесс только по старому PID и
не удаляйте защитные файлы вслепую. Автоматический takeover не выполняется.

Если CLI сообщает об отсутствии входа/разрешений, восстановите его обычный
локальный вход и разрешения. Панель не меняет native permissions удалённо.
Полный native transcript остаётся локальным; на сервер отправляются ограниченные
нормализованные сообщения, не raw terminal, environment или reasoning output.

Native интерфейсы сверены по [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode)
и [Claude Code programmatic CLI](https://code.claude.com/docs/en/headless).
Фактические версии и PASS/FAIL/NOT-RUN ищите в TASK013/WORK, а не выводите из
самого наличия этой инструкции.

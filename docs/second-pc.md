# Второй ПК: подключение к общей очереди

Дата: 18.10.2026. Это инструкция для пилота, а не объявление готовой V1.
Состояние проверок — [TASK-002](TASK-002-publication-readiness.md).

## Сначала выбрать общий сервер

Два ПК должны обращаться к **одному экземпляру Accord и одной серверной БД**.
Клонирование репозитория и запуск `serve` на каждом ПК создадут две независимые
очереди. SQLite-файл не копируют между работающими экземплярами и не размещают
в общей сетевой/облачной папке.

На прежнем VPS сейчас работает отдельный Tandem. Его HTTPS-адрес не является
адресом Accord; токен или код доски Tandem не подходит к Accord. Проверенное
состояние описано в [server-readiness.md](server-readiness.md). Эта проверка
не устанавливала Accord на VPS и не переключала агентов.

Перед подключением второго ПК администратор готовит один из вариантов:

1. Общий Accord на Linux/macOS с проверенным HTTPS-прокси, доступным обоим ПК.
   Сервер слушает только loopback; наружу открывается HTTPS-прокси с сохранением
   Authorization и ограничением запросов. Готового production-развёртывания
   этот пилот пока не содержит.
2. Для временной проверки — Accord на первом Mac и SSH-туннель со второго ПК.
   Первый Mac должен оставаться включённым, а SSH-доступ к нему уже настроен
   администратором. Права на удалённый вход эта инструкция автоматически
   не меняет. На первом Mac Accord слушает `127.0.0.1:8080`.

Туннель запускают на втором ПК и оставляют терминал открытым (OpenSSH доступен
на macOS/Linux; на Windows нужен установленный OpenSSH Client):

```sh
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:18080:127.0.0.1:8080 USER@FIRST_MAC
```

`USER@FIRST_MAC` заменяют реальным SSH-логином и адресом, полученными приватно.
Отпечаток SSH проверяют по независимому каналу; проверку ключа не отключают.
Для этого варианта клиентский адрес Accord — `http://127.0.0.1:18080`.
Между ПК трафик защищён SSH; открытый HTTP-порт по сети не публикуется.

## Отдельный токен второго ПК

На машине сервера, в каталоге с используемой БД, администратор создаёт новый
токен. Сначала проверьте путь: другая БД означает другой экземпляр очереди.

```sh
umask 077
mkdir -p .local
chmod 700 .local
bin/agent-board token create --db .local/board.db --owner second-owner --machine pc-2 --days 30 --output .local/pc-2.token
```

`second-owner` заменяют именем участника. Сохраняют выданный ID для отзыва.
Файл передают владельцу второго ПК приватным защищённым способом, без чата,
Git, скриншотов и вывода содержимого в терминал. Исходный токен администратора
не копируют. На втором ПК сохраняют файл вне репозитория, например
`~/.config/accord/pc-2.token`; на macOS/Linux — каталог0700, файл0600.
На Windows доступ к файлу должен быть только у текущего пользователя через
ACL; POSIX-команду chmod там не используют.

Для временного варианта с первым Mac после сборки и выпуска токена запустите
сервер в отдельном терминале из того же checkout и оставьте его работающим:

```sh
bin/agent-board serve --db .local/board.db --listen 127.0.0.1:8080
```

Затем на втором ПК запускают приведённый выше SSH-туннель. Доступность
проверяют по `http://127.0.0.1:18080/readyz`: ожидается HTTP200. Для общего
HTTPS-сервера проверяют `/readyz` по выданному адресу. Health/readiness сами
по себе не подтверждают наличие авторизованного доступа к очереди.

## Codex CLI

Нужен установленный и авторизованный Codex CLI. На проверенном Mac использован
Codex `0.163.0-alpha.10.2`; приложение другого выпуска требует своего smoke.
Официальные настройки MCP:
[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Добавьте в `~/.codex/config.toml` второго ПК, сохранив существующие разделы:

```toml
[mcp_servers.accord]
url = "http://127.0.0.1:18080/mcp"
bearer_token_env_var = "ACCORD_TOKEN"
required = true
```

Для HTTPS-сервера замените URL на его **реальный** HTTPS-адрес с `/mcp`.
В этой инструкции не выдуман публичный адрес. Токен в config.toml не вставляют.

В терминале macOS/Linux перед запуском клиента:

```sh
export ACCORD_TOKEN="$(cat "$HOME/.config/accord/pc-2.token")"
codex
unset ACCORD_TOKEN
```

В PowerShell (путь адаптируйте к приватному расположению файла):

```powershell
$env:ACCORD_TOKEN = (Get-Content -Raw "$env:USERPROFILE\.config\accord\pc-2.token").Trim()
codex
Remove-Item Env:ACCORD_TOKEN
```

Эти команды не печатают секрет и не записывают его значение в историю.
Переменная действует для клиента, запущенного из этого терминала; уже открытое
GUI-приложение её автоматически не получает. Не добавляйте значение токена
в настройки агента, профиль оболочки или системную общую переменную.

После запуска откройте `/mcp`: Accord должен быть подключён. Затем поручите
агенту использовать только Accord: открыть `describe` с `machine=pc-2`, новой
меткой `run_id`, уникальным `request_id` и ролью coordinator; получить
тестовый эпик, созданный с первого ПК; прочитать events. Номер эпика берут из
фактического ответа первого ПК. Не используйте реальные задачи для smoke.

Для полной проверки двух машин создают отдельную синтетическую developer-задачу
и одновременно запрашивают её через `next` из двух разных developer-сессий.
Только одна должна получить аренду. Сохраняют версии клиентов, key/generation,
курсоры и результаты без токенов. Затем проверяют heartbeat, release, повтор
того же request_id и возврат после разрыва связи. Такие результаты пока нельзя
считать выполненными: доступа ко второму физическому ПК в этой работе нет.

## Рабочие ограничения

- `describe` открывают заново для роли/запуска; `session_id` передают далее.
  Координатор не захватывает задачу для передачи другому агенту.
- При TTL15 минут клиент отправляет heartbeat не реже чем раз в5 минут,
  включая во время долгой работы без других вызовов. Наличие MCP-инструмента
  не запускает фоновый heartbeat. Его интеграция ещё требует проверки.
- При разрыве связи, неоднозначном результате или LEASE_LOST прекращают
  локальные изменения и сверяют владение. После неоднозначного ответа
  повторяют тот же request_id с тем же payload.
- Accord защищает изменения очереди, но не блокирует файлы на другом ПК.
  Рабочие копии и границы редактирования согласуют отдельно.
- Claude Code, Windows/Linux runtime и физическая работа двух ПК требуют
  отдельных проверок; совместимость Codex на одном Mac их не заменяет.
- Отзыв токена выполняет администратор на сервере:
  `bin/agent-board token revoke --db .local/board.db --id TOKEN_ID`.

Если нужно только изучить исходники на втором ПК, установите Git и Go1.26.1+
и клонируйте ветку `codex/pilot`:

```sh
git clone --branch codex/pilot https://github.com/kirill-samylin/accord.git
cd accord
go build -o bin/agent-board ./cmd/agent-board
```

На Windows для сборки используйте `go build -o bin/agent-board.exe ./cmd/agent-board`.
Сборка клиента не требуется для подключения Codex через MCP. Запуск Windows
сервером не подтверждён и этой инструкцией не предлагается.

## Замечания для исправления

### A2-01 — P1: реальный Codex не подключается к MCP

Место: `internal/transport/mcp.go:18`.

Сервер ограничен `SupportedProtocolVersions: [2026-07-28]`. Координатор
на установленном Codex CLI `0.163.0-alpha.10.2` получил HTTP 400
`Unsupported protocol version` при initialized notification. Это фактический
результат координатора, не мой самостоятельный запуск клиента; локальный
лог — `.local/evidence/codex002/codex.jsonl`. SDK smoke текущего протокола
проходит, но не подтверждает совместимость этого Codex.

Pinned SDK v1.8.0 содержит поддержку `2025-11-25`, в том числе stateless
HTTP и проверку ограниченного списка поддерживаемых версий. Нужно включить
обоснованный совместимый вариант через штатный `ServerOptions`, добавить
SDK-тест обеих версий и повторить вызов реального Codex. Не подменять handshake
собственным JSON-RPC. До проверки подключение второго ПК по MCP не обещать.

### A2-02 — P2: отменённый эпик продолжает выдавать задачи

Место: `internal/store/tasks.go:97`; связанное место —
`internal/store/transitions.go:102`.

Создать ready-задачу, отменить её эпик с причиной, затем вызвать `next` этой
роли: задача успешно становится in_progress. Отмена эпика запрещает новые
create, но очередь игнорирует состояние родителя. Работа отменённого эпика
продолжается сразу после явного решения координатора её остановить.

Нужно исключить задачи cancelled-эпика из обычного и точечного next; возврат
эпика в open должен разрешать выдачу снова. Историю и состояния дочерних задач
сохранять; автоматический каскад cancel без отдельного решения не требуется.

### A2-03 — P2: stale generation переключается на административное право

Места: `internal/store/tasks.go:134–139`,
`internal/store/dependencies.go:45–50`.

Когда lease истекает, expire переводит задачу в ready и очищает lease.
Update с явно переданным прежним generation после этого успешно выполняется,
если тот же principal является requester либо сессия — coordinator.
Lease-bound запрос молча превращается в редактирование незахваченной задачи;
в Link такой же путь позволяет менять зависимости. На типичном пилотном
токене несколько сессий имеют одного requester-principal.

Нужно различать намеренное административное изменение без generation и запрос
к конкретной аренде. При переданном поколении требовать живую lease и совпадение
владельца/поколения; иначе LEASE_LOST без metadata/link/event/TTL изменений.
Requester/coordinator без generation сохраняет документированные права на
незахваченную работу. Добавить регрессии expiry, release и повторного claim.

### A2-04 — P2: CLI выдаёт обрезанный ответ как успех

Место: `cmd/agent-board/client.go:83–93`.

`io.LimitReader(..., 1<<20)` не сообщает переполнение. При ответе больше
1 МиБ клиент выводит первые 1 048 576 байт и возвращает exit 0, даже если
JSON обрезан. Размер task растёт с comments/attempts, поэтому лимит ответа
можно превысить при допустимых отдельных запросах. Особенно опасен обрезанный
ответ успешной мутации: клиенту недостаёт полной информации о владении.

Нужно прочитать максимум limit+1, обнаружить превышение, вернуть явную ошибку
с рекомендацией сверить владение и не представлять обрезанный JSON успешным
результатом. Проверить ответы меньше, ровно и больше лимита.

## Границы заключения

Физический второй ПК, Claude Code, удалённый Accord/TLS, нагрузочные цели,
OAuth и оставшаяся V1 этим аудитом не проверялись. Дорожная карта честно
отделяет их от локального ядра. Публикация проверенной ветки пилота допустима
после исправления замечаний и актуальной повторной проверки; этот отчёт
сам по себе не разрешает обещать готовый сервер вместо Tandem.

Положительные стороны: транзакции и lease fencing централизованы; отклонённая
мутация изолирована от candidate state; отрицательный review не открывает
gate; глобальные review-обязательства и SHA/generation учитываются; секрет
токена не хранится в БД; DB/sidecars проверяются до SQLite IO.

Отложенная рекомендация: уточнить обязательность полей MCP-схемы для epic
(Go DTO требует role/priority, хотя REST-пример epic их опускает) и в следующей
задаче решить пагинацию растущих attempts/comments. Это не добавляет к текущей
дельте нового блокирующего объёма.

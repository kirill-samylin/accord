# Задание агенту на втором компьютере

> Дополнение веб-версии19.10.2026: человеку достаточно открыть существующий
> HTTPS-адрес и войти по своему токену/файлу токена. Четыре раздела описаны в
> [руководстве веба](web-guide.md). Установка MCP нужна только агенту.
> Для ресурсов загруженного дизайна обновите старый клиент1e9025c до6245829
> из проверенного платформенного архива и перезапустите MCP; адрес и токен
> остаются прежними. Старый клиент сохраняет прежние12 инструментов, но
> не показывает новые design resources. Таблица старых архивов ниже относится
> к предыдущему выпуску и не является пакетом обновлённого веб-клиента.


Актуально 19.10.2026: подключаем Accord через обычный публичный HTTPS.
Tailscale для этого подключения не требуется. Секрет в текст задания не вставляется.

---

Подключи этот компьютер к нашему Accord. Прочитай docs/public-https.md и
новую docs/second-pc.md из ветки codex/pilot. Старые шаги с Tailscale/8443
заменены новым порядком. Не подключай Tandem и не устанавливай новый сервер.

1. Найди отдельно переданный ОБНОВЛЁННЫЙ connection.json и прежний pc-2.token.
   Если их нет, сообщи владельцу только названия отсутствующих файлов. Адрес
   возьми из origin. Токен читай только в память клиента, не печатай и не
   помещай в Git, TOML, аргументы, shell history или отчёты.
2. Если client уже установлен, используй его: agent-board1e9025c совместим
   с новым HTTPS. Go и пересборка не нужны. Если нет — выбери готовый клиент
   своей ОС/архитектуры из нового пакета и проверь SHA256.
3. В локальном MCP-конфиге Codex сохрани другие настройки и замени значение
   после --server на точный origin из нового JSON. JSON клиент не читает
   автоматически. Сохрани абсолютные пути к бинарнику/токену. На POSIX файл
   токена0600/каталог0700; Windows — ACL текущего пользователя и передача
   AGENT_BOARD_TOKEN в новый Codex CLI из защищённого файла, без literal secret.
4. Перезапусти локальный Codex. Проверь HTTPS /readyz с нормальной проверкой
   сертификата, MCP initialize и tools/list12. IP в HTTPS допустим, если это
   точный выданный origin и сертификат действителен; TLS-проверку не отключай.
5. Открой собственную сессию describe: role=coordinator, machine=pc-2,
   свежие run_id/request_id. Создай свой epic TEST pc-2 public HTTPS:
   type=epic, title/description, role="", priority=2 и новый request_id.
   Прочитай выданный ключ через get/events; отмени только его через transition:
   task_key=выданныйключ, generation=0, state=cancelled,
   reason="synthetic cleanup", новый request_id. Все required-поля tools/list
   передавай явно. Через worker session_id подставляется автоматически.
6. Один worker — одна роль/запуск. Заверши свой worker после проверки.
   Чужие задачи и аренды не изменяй. Отчитайся без секретов: ОС/архитектура,
   SHA клиента, TLS/readiness, MCP/catalog, synthetic key/cleanup/next_cursor.

Реальный запуск на этом ПК подтвердить отдельно: проверка с первого Mac
его не заменяет. Совместный claim/heartbeat двух физических ПК — следующий
отдельный сценарий. Новые продуктовые срезы, merge/main и VPS не изменяй.

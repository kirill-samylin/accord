# Задание агенту на втором компьютере

Передайте текст ниже агенту в локальном приложении на втором ПК после получения
client ZIP, отдельного `connection.json` и защищённого `pc-2.token`.
Пути назначает владелец этого компьютера; секреты в текст задания не вставляются.

---

Принимаем самостоятельный проект **Accord** и подключаем этот компьютер
к уже работающему общему серверу. Сначала выполни клиентское подключение,
затем зафиксируй состояние исходников. Начинать новые продуктовые срезы не нужно.

1. Если checkout ещё нет, из корня распакованного пакета выполни
   `git bundle list-heads ./accord.bundle`, `git clone ./accord.bundle accord`;
   в созданном accord — `git bundle verify ../accord.bundle` и
   `git checkout codex/pilot`. Если локальной ветки нет:
   `git checkout -b codex/pilot origin/codex/pilot`.
   Работай в этой папке Accord, не в соседнем Davinci. Прочитай `AGENTS.md`,
   `docs/handoff.md`, `docs/TASK-003-working-service.md` и `docs/client-setup.md`.
   Профили ролей при необходимости доступны в `process-reference/` пакета
   передачи. Это справочный процесс; локальный AGENTS Accord имеет приоритет.
   **Tandem off**: не подключай его MCP/доску, не ищи canvas code и не создавай
   на нём задач. Имя хоста может содержать tandem, но Accord имеет свой порт8443.
2. Найди отдельно переданный `connection.json` в корне распакованного
   `Accord-project.zip` (он доставляется рядом с ZIP и добавляется после распаковки).
   Возьми из него реальный
   `origin` и `machine=pc-2`. `pc-2.token` читать разрешено только в память
   клиента для авторизации; никогда не печатай/копируй его в ответы, source,
   TOML, аргументы, shell history или диагностический вывод. Не выводи окружение.
   Если файлов нет, укажи конкретный отсутствующий файл владельцу; адрес Tandem
   не запрашивай и токен другой машины не используй.
3. Определи ОС/архитектуру; выбери соответствующий готовый client ZIP1e9025c,
   проверь SHA256 архива и бинарника по манифестам. Собирать Go для доступа
   не требуется. Проверь Tailscale и HTTPS `origin/readyz` с обычной TLS-проверкой.
   Не выключай сертификаты, не меняй DNS на IP и не запускай локальный `serve`.
4. Если Accord MCP отсутствует в текущем приложении, настрой его **локально
   на этом хосте**, сохранив существующие настройки. Для Codex используй
   `~/.codex/config.toml` и раздел `accord_worker` из handoff: абсолютный binary
   path, `mcp --server <origin>`, POSIX token-file либо Windows AGENT_BOARD_TOKEN.
   На Windows токен загружается из ACL-защищённого файла в окружение нового CLI,
   без literal secret в командах. Если требуется перезапуск приложения, сохрани
   checkpoint и сообщи владельцу этот конкретный следующий шаг. Изменение
   репозитория не создаёт доступ к инструментам в облачной/другой среде.
5. Проверь MCP initialize и tools/list: у live C2 ожидаются12tools. Открой
   собственную board-сессию через `describe` с role=coordinator, machine=pc-2,
   свежими уникальными run_id/request_id. Один stdio worker обслуживает только
   одну роль/сессию; для другой роли нужен новый запуск. Не предоставляй один
   долгоживущий worker нескольким независимым агентам.
6. Создай собственный synthetic epic `TEST pc-2 connection` с описанием
   проверки. Прочитай его get/events, сохрани выданный ключ и next_cursor.
   Отмени только этот эпик через transition(state=cancelled,
   reason="synthetic cleanup", новый request_id). Чужие задачи не брать
   и не менять. Затем заверши отдельный worker: heartbeat прекратится,
   board-сессия истечёт по TTL; публичного session close здесь нет.
7. Сверь HEAD/ветки с манифестом. Не сливай ветки и не меняй origin/main/VPS
   автоматически. Ветки с D4/E не равны установленной live-версии C2.
8. Дай краткий отчёт без секретов: ОС/архитектура, версия и SHA клиента,
   readiness/TLS, MCP initialize/catalog, session_id и synthetic key/cleanup,
   next_cursor, текущая Git-ветка/SHA и фактические ограничения. PASS/FAIL/NOT-RUN
   указывай отдельно. Проверку с Mac ранее не выдавай за запуск на этом ПК.

Доступ по отдельным машинным токенам согласован; OAuth-приложение не требуется.
Если связи нет, диагностируй Tailscale/ACL/точный origin/порт/token срок согласно
handoff. Не меняй сервер и Tandem ради клиентской диагностики. Два физических
ПК ещё должны совместно проверить атомарный claim/heartbeat/expiry; успешный
одиночный smoke не закрывает этот этап. Проект целиком пока не объявлен V1 ready.

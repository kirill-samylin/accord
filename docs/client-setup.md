# Клиенты Accord: доступ и аренды

Первый рабочий доступ — отдельный локально выданный токен каждой машины.
GitHub OAuth отложен пользователем. Фактический статус сервера и проверок
фиксирует [TASK-003](TASK-003-working-service.md); наличие этой инструкции
само по себе не означает выполненную проверку второго ПК.

## Подключение одной командой

Для обычного участника достаточно собственного файла токена, который панель
выдаёт вместе с `connection.json`. Положите оба файла в одну папку и выполните
(WORK297; клиент старше этой версии команды не содержит):

```text
agent-board connect --token-file /ABSOLUTE/PATH/accord.token
```

Команда ничего не спрашивает: читает адрес сервера и ID проекта из
`connection.json` рядом с токеном (или из `--server`/`--project`), сохраняет
приватную копию токена и клиента в `~/.config/accord/` (каталог `0700`, токен
`0600`), находит установленные Codex, Claude Code и Gennadiy и регистрирует в
каждом MCP-сервер `accord`: Codex и Claude Code — через их собственные
`mcp add`, Gennadiy — записью `mcp.accord` в `~/.config/gennadiy/gennadiy.json`
с сохранением остальных ключей. Файл с комментариями не трогается: команда
печатает готовый фрагмент для ручной вставки. Сам токен в аргументах и выводе
не появляется.

После этого откройте свой CLI в папке проекта и попросите агента взять
следующую задачу. Аренды доски (`describe → next`) не дают двум людям взять
одну задачу; удалённое управление компьютером для этого не требуется, оно
описано отдельно в [managed-worker-guide](managed-worker-guide.md).

## Два способа подключения

**Stdio bridge для отдельного запуска агента.** MCP-клиент запускает локальный
`agent-board mcp`; мост обращается к общему HTTPS-серверу и продлевает текущую
аренду. Один bridge — одна board-сессия с одной ролью. Процесс должен завершаться
вместе с исполнителем. Для смены роли нужен новый запуск. Долгоживущий общий
bridge для нескольких независимых ролевых агентов не используется: он не знает,
завершился ли конкретный исполнитель внутри другого приложения.

**Прямой Streamable HTTP для клиента, который разделяет MCP между агентами.**
Каждый исполнитель вызывает describe с собственной ролью/run_id/request_id,
передаёт полученный session_id и самостоятельно поддерживает heartbeat.
Прямой HTTP не создаёт фонового таймера. Не обещайте автоматическое продление
для внутренних субагентов IDE без проверки её жизненного цикла MCP.

Оба способа используют один сервер и одинаковые правила. При потере связи
и LEASE_UNCERTAIN/LEASE_LOST прекращают локальные изменения и сверяют владение.
Запрет мутаций мостом не останавливает IDE, shell или файловый редактор.

## Stdio на macOS/Linux

Соберите клиент согласно README. В конфигурации MCP задайте абсолютные пути:

```toml
[mcp_servers.accord_worker]
command = "/ABSOLUTE/PATH/agent-board"
args = ["mcp", "--server", "https://ACCORD_ADDRESS", "--token-file", "/ABSOLUTE/PRIVATE/PATH/pc-2.token"]
required = true
```

Это пример конфигурации Codex, а не файл с действительным адресом/секретом.
Исполняемый файл должен находиться на клиентском ПК; токен — в каталоге0700,
файл0600. В конфиг попадает путь, не значение. При отдельном запуске Codex CLI
мост завершается вместе с процессом; реальная совместимость другого приложения
и его внутренних субагентов проверяется отдельно.

Первый вызов — describe с machine, совпадающей с выданным токеном. Каждый
новый запуск использует новые run_id/request_id. После describe session_id
можно опускать только через bridge: он подставляет свою сессию. Любой иной
session_id отвергается. Прямой HTTP требует session_id явно.

## Windows: передача токена через окружение

Сборка Windows amd64 проверяется отдельно от запуска. Проверки POSIX-модов
файла клиента не являются проверкой ACL Windows, поэтому для этого варианта
используется существующий путь AGENT_BOARD_TOKEN. Сам файл защищают ACL
текущей учётной записи и читают в окружение, не печатая значение:

```powershell
$env:AGENT_BOARD_TOKEN = (Get-Content -Raw "$env:USERPROFILE\.config\accord\pc-2.token").Trim()
codex
Remove-Item Env:AGENT_BOARD_TOKEN
```

Настройки соответствующего worker MCP:

```toml
[mcp_servers.accord_worker]
command = "C:\\ABSOLUTE\\PATH\\agent-board.exe"
args = ["mcp", "--server", "https://ACCORD_ADDRESS"]
env_vars = ["AGENT_BOARD_TOKEN"]
required = true
```

Не вставляйте значение в TOML, командную строку или профиль оболочки.
Клиент запускают из подготовленного терминала; уже открытый GUI его окружение
автоматически не получает. Этот вариант остаётся NOT-RUN на физическом Windows
ПК до проверки пользователя.

## Прямой HTTP в Codex

Для отдельного профиля/клиента с явным heartbeat:

```toml
[mcp_servers.accord]
url = "https://ACCORD_ADDRESS/mcp"
bearer_token_env_var = "AGENT_BOARD_TOKEN"
required = true
```

Переменную получают из приватного файла в запускающем терминале. Не включайте
одновременно direct и worker серверы с ожиданием, что они делят одну сессию:
это разные клиентские подключения, их роли и обязанности задаются явно.
При default TTL15 минут heartbeat отправляется минимум каждые5 минут,
с текущими task_key/generation и role_generation. Чтения/replay этого не делают.

Официальные настройки:
[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
Фактические версии и результаты в отчёте не распространяются автоматически
на Claude Code или другой релиз клиента.

## Проверка второго ПК

Получите реальный частный HTTPS-адрес и отдельный токен по защищённому каналу.
Подключите ПК к той же Tailscale-сети. Проверьте /readyz, затем describe/get/
events на отдельном synthetic эпике. С двух машин одновременно запросите
одну developer-задачу через разные сессии: только одна получает аренду.
Проверьте длительную работу, завершение worker, истечение и новый generation.
Запишите версии/ОС и результаты без токенов. Пользователь выполнит физическую
проверку позже; два процесса на одном Mac её не заменяют.

Если HTTPS работает, но MCP initialize возвращает403, оператор проверяет
соответствие `--external-host` сервера реальному DNS-имени и порту клиента
(см. [развёртывание](deployment.md)). Host проверяется точно; нельзя заменять
его IP-адресом, другим портом или выключать защиту SDK без внешнего фильтра.
Токен не обходит проверку Host/Origin. Сервер не доверяет X-Forwarded-Host.

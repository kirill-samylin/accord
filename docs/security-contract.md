# Доступ и безопасность общего Accord

Дата: 18.10.2026. TASK-003; основание — пользователь поручил сначала рабочий
доступ по отдельным токенам. Это контракт перед реализацией и независимым
ревью поставки, **не security approve ещё не развёрнутого сервера**.
Исходная проверенная база: `966dda698da5e615b1517faec853c0b7271b2f9c`.
Требования ядра — [requirements](requirements.md), транспорт — [API](api.md).

## Границы доверия

Активы: задачи и evidence, история попыток/проверок, токены машин, SSH-ключи,
SQLite и backups, generation/idempotency/cursors, исполняемый файл и unit.
Недоверенные входы: HTTP/MCP JSON, Origin/Host/forwarded headers, тексты задач,
пути локальной CLI и полученные от агента идентификаторы/результаты.

Доверены администратор VPS, владелец каталога данных и пользователь машины,
на которой хранится её токен. Допущение — два доверенных участника; локальный
токен даёт роли пилота, в том числе human/coordinator, а не разграничение
администраторов и читателей. Разные токены дают отдельные identity, revoke и
provenance; они **не дают scopes/RBAC или GitHub/browser identity**.

Членство в tailnet ограничивает сеть, bearer ограничивает доступ к данным.
Кража bearer даёт его полномочия до revoke/expiry. Сессионный ID и generation
не заменяют bearer. Root/тот же OS UID может прочитать секреты; от этого
персональный клиентский процесс и SQLite-файл не изолируют владельца машины.
Сервер не запускает shell, не загружает URL evidence и не применяет текст
задач как инструкции. Агент не должен считать содержимое документа разрешением
на внешнюю отправку, выполнение кода или изменение чужого проекта.

### Транспорт и лимиты

Для первого native MCP/CLI запуска простая допустимая Origin-политика:
запросы без Origin разрешены, **любой присутствующий Origin отклонён**.
Альтернатива — exact allowlist канонического HTTPS origin с port; wildcard,
`null`, несколько значений, произвольный forwarded-host не допускаются.
Если выбран exact allowlist, он конфигурируется администратором и тестируется.
Нужна одна определённая политика, а не неявное доверие proxy заголовку.
Безопасные браузерные GET также проверяются для MCP. Не включать CORS `*`.
OAuth/browser UI — отдельный последующий контракт, прежде потребуется
пересмотреть эту native-only политику. Origin не является аутентификацией.

Нельзя отключать SDK localhost/DNS-rebinding защиту целиком ради proxy.
Проверяется, какой Host сохраняет установленный Tailscale Serve; необходимые
доверенные host/origin фиксируются явно. Не верить X-Forwarded-For/Host для
авторизации и rate-limit от произвольного loopback-клиента.

Минимально достаточен общий bounded limiter до дорогой аутентификации,
например100 запросов/с с burst200, плюс ограничение concurrent requests.
Если используется limiter по principal, ключ — проверенный token ID, не
сырой bearer; число bucket и срок их хранения ограничены. Значения являются
техническими defaults и должны не мешать двум рабочим клиентам/heartbeat.
Искусственный429 проверяется в отдельном стенде с меньшим порогом, а не
нагрузкой существующего VPS/Tandem. Не обещать DDoS-защиту частного сервиса.

Существующие body64КиБ, header16КиБ, header/read/write/idle timeouts сохраняются.
Health/ready раскрывают только минимальный status; они не открывают board.
К no-store добавить `X-Content-Type-Options: nosniff`. Для API допустимы
`Referrer-Policy: no-referrer` и CSP default-src 'none'/frame-ancestors 'none';
новый UI позже требует собственного CSP. HSTS на HTTPS-прокси полезен,
но отсутствие HSTS не заменяет обязательную проверку TLS клиентом.

### Bootstrap и работа с секретами

Токены создаются существующей локальной CLI с ≥256 бит случайности; в БД
остаётся SHA256. Выводится token ID/expiry и путь, не Secret. Процедура
оператора хранит outputfile в закрытом0700 каталоге; его parent/путь не
передаётся произвольному непривилегированному пользователю root-wrapper.
Новый файл создаётся O_EXCL0600; существующий не перезаписывается.

Передача клиенту — существующим SSH/SCP с закреплённым known_hosts;
секрет не вставляется в chat, Markdown, shellhistory, флаг команды или Git.
На Mac токен остаётся0600 в закрытом каталоге. На Windows требуется ACL
только учётной записи пользователя; успешная кросс-сборка не доказывает ACL.
Предпочтителен stdio bridge с `--token-file`: значение отсутствует в MCP
конфигурации; stdout содержит только протокол. Child process получает токен
лишь при необходимости, не весь набор секретов окружения родителя.

Токен второго ПК можно выдать непосредственно перед подключением, чтобы
срок не истекал в ожидании. Отсутствие второго ПК не повод повторно
использовать токен Mac. Проверка двух synthetic токенов сейчас и двух
физических машин позже — разные результаты.

Отзыв делает токен непригодным, включая ранее сохранённый replay. Он не
обязан немедленно снимать tasklease: lease закономерно истекает, старый
исполнитель больше не продлевает её. Нельзя освобождать чужую работу
административным SQL или сбрасывать generation для ускорения переключения.

### Служба, данные и восстановление

systemd: User/Group accord, UMask0077, Restart=on-failure, NoNewPrivileges,
ProtectSystem=strict, ProtectHome, PrivateTmp, ограниченные writable state/runtime
paths, пустой capabilityset. Защиты должны оставлять loopback/AF_UNIX и
SQLite locks доступными. Binary и release symlink изменяет только администратор;
service не устанавливает себе обновление. Resource caps соразмерны VPS1ГиБ
с работающим Tandem: MemoryMax/TasksMax и RestartSec без restartloop.
systemd-analyze verify и фактический запуск дополняют статическую проверку.

Backup: SQLite online backup либо согласованная offline процедура после
остановки всех DBwriters с обязательным восстановлением службы при ошибке.
Копировать только live `board.db` при WAL нельзя. Backup закрыт0600 в0700dir,
временный файл создаётся безопасно, публикация atomic, SHA256 фиксируется.
Checksum подтверждает целостность, а не конфиденциальность. Нужны расписание,
ограниченная retention и видимый статус последнего успеха. На одном VPS
backup не защищён от потери самого VPS; offsite требует отдельного места,
эта граница указывается без обещания отсутствующей копии.

Restore drill использует отдельный закрытый каталог/loopbackport и synthetic
данные. Проверяется не только integrity_check, но task/evidence/history,
idempotency и отозванный token. Восстановленная живая lease не считается
действующей после серверного expires_at; время/generation не сбрасываются.
Backup содержит credential hashes и историю, поэтому он конфиденциален.
Нельзя накатывать backup с прежним активным токеном, не учитывая последующие
отзывы. Для выбранного TASK-003 restore обязательна offline recovery-процедура
до открытия сети: **отозвать все восстановленные токены и инвалидировать
восстановленные сессии/их аренды**, затем выдать новые токены. Обновление
атомарно, оставляет аудит и закрывает незавершённые попытки с причиной restore;
task/role generation сохраняются монотонными и никогда не сбрасываются.
Это намеренное восстановление с новыми identity, а не обещание продолжить
старые сессии. Негативная проверка: token, отозванный после момента backup,
после restore по-прежнему не работает; старые session/generation не работают
даже с новым bearer. Обычный backup drill до recovery отдельно доказывает
точность snapshot; после recovery отдельно проверяет безопасную инвалидизацию.

Rollback бинарника без изменения схемы — смена root-owned release pointer
и restart с health/ready. При несовместимой схеме старый binary обязан
отказаться; восстановление старого DBbackup отдельная разрушительная
операция с явно названной потерей более поздних транзакций.

### Heartbeat bridge и права локального агента

Пульс работает отдельно от занятой модели; новый request_id на каждый tick.
Он использует только подтверждённые session/task/role generations, никогда
не получает новую роль/задачу автоматически после потери старой. Interval
меньше минимального TTL, обычно ≤TTL/3; HTTP deadline оставляет запас до expiry.
Heartbeat/release одной сессии сериализуются, чтобы завершение/освобождение
не оставляло фонового продления устаревшего состояния. Чужой session_id
не даёт bridge право обслуживать её вместо локально открытой сессии.

При сетевой неопределённости, UNAUTHORIZED, LEASE_LOST, expiry или ошибке
декодирования bridge показывает явную ошибку и не продолжает servermutations
со stale состоянием. Читающие диагностические вызовы допустимы; возобновление
требует проверки владения. Никаких silent reacquire с новым generation.
EOF/сигнал завершают таймер и процесс; допустим best-effort release только
действительно удерживаемого поколения, без массового снятия аренд.

Bridge не останавливает самостоятельный shell/edittool Codex/Claude. Поэтому
инструкция клиента обязана требовать прекратить файловые записи при потере
связи/lease и сверить серверное владение перед продолжением. Нельзя заявлять,
что heartbeat или fencing физически запрещает edits отключённого компьютера.
Нужны отдельные negative tests на networkfault/revoke/expiry и реальный
remote Codex; второй физический ПК и Claude отмечаются отдельно.

## Доказательства перед выпуском

Независимый reviewer/security фиксирует конкретные hashes новой реализации.
После approve отдельный tester проверяет remoteTLS, auth/revoke/replay,
Origin/limits, restart и backuprestore, длительный пульс и его потерю.
Проверяются разные logical clients; два процесса на Mac не называются двумя
физическими ПК. Все реальные secrets/hostname/keypaths остаются в .local,
в Git только обезличенные команды, результаты и checksum артефактов.

## Первичные источники, проверены18.10.2026

- [Go CrossOriginProtection](https://pkg.go.dev/net/http#CrossOriginProtection):
  safe methods всегда допускаются, поэтому его одного недостаточно для
  заявленного запрета Origin на всех MCP запросах.
- [Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve):
  Serve публикует внутри tailnet; Funnel имеет публичный охват. Конкретная
  установленная конфигурация и отсутствие Funnel проверяются отдельно.
- [SQLite Online Backup](https://www.sqlite.org/backup.html): согласованный
  snapshot через backup API отличается от сырого копирования активной БД.
